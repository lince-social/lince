Database migrations are append-only. Never edit, delete, rename, or renumber an existing file in crates/store/migrations, including whitespace. Never change or remove an existing entry in crates/store/migrations.sha384, or bypass the build guard. Change the schema with a new migration whose number is greater than every existing migration number. Append its filename and exact SHA-384 checksum to crates/store/migrations.sha384 using sha384sum. Run cargo check -p store and the migration_guard tests before continuing. A past migration needs a correction in a new migration, never a rewritten checksum.
