# Reading the interface notes

Start with [Interface in Lince.lingua](../Lince.lingua). It holds the owner's explanation, wishes and progress marks. Only the owner edits it.

[The interface draft](plans/interface.md) gathers the remaining markdown material into short explanations and proposed tasks for manual review. It combines existing wishes with additions, so merge it with the Record rather than appending a second copy of the same tasks.

The other files explain individual subjects. They no longer carry separate implementation checklists. [Coverage](coverage.md) shows where their material went. [Research links](links.md) keeps useful references separately from proposed work.

The direction is Bevy for the native application, Flair for styling and Avian for later physics. Everyday placement stays flat and stationary first. The old Web crate remains unplugged and untouched. Websites and formerly browser-backed content still need a workable design under the current no-embedded-browser direction.

Earlier documents mixed prototype results, old Web features, task codes and future promises. Their completion counts did not establish what the current Bevy interface can do. This prose rewrite makes no new implementation claims. Check the current source and running controls when taking a task from the Record; keep its existing completed items intact.

The Facade notes also disagreed about whether visitors contact a live server or retrieve public copies privately. That choice remains visible in [Facade](facade.md). The draft does not silently settle it.
