# Making Lince look like yours

The default is flat, quiet and readable, using the palette in [Lince.lingua](../Lince.lingua). Zed is a reference for clear text, restrained controls and responsiveness. Lince should keep its own appearance.

Common controls cover colors, fonts, spacing, gaps, size, borders, roundness, density and motion. Light and dark defaults are complete; a partial custom theme inherits whatever it leaves out. Typography must cope with Portuguese, English, long content, zoom and chosen fonts.

Settings have a visible scope. Defaults and component rules are followed by definition defaults, theme, workspace, group and instance choices. Show where a value comes from and offer Inherit, which removes the local override. Changing one appearance of Apple should leave Pear and another Apple appearance alone.

Use Flair for CSS styling over Bevy. Configuration controls edit the same stored inputs that advanced styling uses, so two systems do not fight over the same property. Explain supported CSS, refuse unsafe assets or excessive work, and retain the last working style after an invalid edit. A released child keeps its logical group's styling even when its movement changes.

An unreadable or invalid settings file opens safe defaults without overwriting the rejected bytes. A failed save must not be reported as durable. Keep Reset outside the customized content. Registered local style extensions retain their declared types, and theme assets retain their identity and integrity checks.

Appearance, Connections and Data can be edited separately or together. Choosing a simpler view of the settings preserves everything hidden. Workspace controls start visible and can fold into a configurable triangle; a keyboard action must always restore them.

Use shared style values for interface controls. Drawings, wallpapers, charts and other user content can have their own colors and geometry. Opaque content and restrained shadows are the default. Solid and dashed lines carry settled and declared meaning, and color is never the only sign of a state.

Text and borders should stay sharp at the actual display scale, including transformed Sands. Reduced motion changes behavior, and ordinary control responses remain immediate. Review the controls through the same Gallery or Laboratory that exercises composition, focus and reset.

Flair's convenience does not establish its cost. Measure idle use, one animated control among static ones, a targeted edit and a theme reload. Fix measured problems without creating a second styling framework.

Later shader editing starts with a supported fragment-effect profile. Limit inputs, bindings, work and the margin used by outward glow; glow does not enlarge the click target. Vertex or compute shaders and scene lighting need separate designs. Successful compilation does not prove an effect is affordable or safe to run, so preserve last-good preview, reduced motion and external Disable through errors and device recovery.

The proposed tasks are in [Appearance and controls](plans/interface.md#appearance-and-controls). [Visual inventory](visual-inventory.md) explains what to carry over from the old interface.
