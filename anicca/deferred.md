# Ideas kept for later consideration

These notes preserve possibilities for the owner to choose from. They have no implementation order and are mentioned separately at the end of [the interface draft](plans/interface.md#ideas-to-keep-separate).

**Offline workspace copies.** People could edit while the host is unavailable and merge later, or deliberately replace a lost host. This needs rules for conflicting layout, definitions, Areas and motion, plus membership, encryption, recovery and limits. Revocation stops future access but cannot erase copies already received. Live host-based sharing can be useful before this exists.

**Richer Protein selection.** Slug or Concept patterns and filters through related Karma data could make views more expressive. Any pattern matching needs understandable failures and bounded work. Use current Protein capabilities until those reads exist.

**Previewing a description becoming data.** Show which Records and Assertions a Lingua description or Ontology Trail would create, including intermediate steps, before applying ordinary authorized Actions. The [Morpho example](https://github.com/paradigms-of-intelligence/morpho) prompted this idea. Try the existing language and primitives before proposing another language or runtime; a preview remains separate from committed data.

**Portals and multiple planes.** A hole into another workspace could show and interact with it while keeping its ownership, coordinates and events separate. Multiple physical planes, including a movable hover plane, require clear collision and navigation rules. They are additional work beyond one workspace's surface or free-space mode.

**Formulas and richer materials.** Editable mathematical terrain, deeper displacement and more elaborate lighting could follow simple brushes and surface effects. Prefer ordinary notation and presets, with bounded evaluation and clear explanations. Content MathML and OpenMath were possible storage references, not a chosen formula engine.

**Smaller Calendar primitives.** Calendar and Clock are already wishes in Lince.lingua. Only decomposing their specialized time view into still smaller pieces remains exploratory.

**Untrusted executable extensions.** Current extension work uses editable registered components and trusted Rust plugins. Installing arbitrary code needs its own isolation, permissions, resource limits and update review. Inspecting package metadata does not authorize running it.

**Other media and devices.** Drawing inside a Record body can use referenced raster assets. Mobile, XR, deeper media editing and general spreadsheet formulas remain separate possibilities. Specialized native document, terminal, video and game support is described in the draft; those replacements do not imply a general plugin sandbox.

The earlier mobile wish follows a completed desktop workspace and should not delay that work. Revisit that order with the owner if mobile becomes a priority. Formula evaluation, if chosen, must be bounded and cannot perform file, network or Action operations.

[World and production notes](future-sands.md) keeps maps, spatial scenes, production and commerce ideas. The [terrain demonstration](https://youtu.be/-IOLRcFC6OY?si=WW1tMdMmo0NYxcu_) is a visual reference, not a requirement to reproduce it.
