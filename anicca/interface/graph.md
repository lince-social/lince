## What a proof means

`bash scripts/interface/part-a-proof.sh Gnn --candidate` runs the node's named tests in its declared native lane, normally scoped Corgi. `--integrated` runs them on the integrated tree with the same native features, re-proves the accumulated certified set and executes the node's required fresh native witness. Cargo/Nix is used for production/package proof and where assigned by the build rule, not as a requirement to repeat every deterministic test under both compilers. No Part A command enables CEF or joined features. The runner records commands, exit codes, nonzero test counts, source/feature identity, selected tool and report paths and fails on a skipped test, missing witness or stale report.

Each workflow's `part_a_<name>` test target must call production definitions, input routing and domain adapters. At least one positive and one refusal/empty case are required, plus refresh and teardown. Its live witness opens the root in the real host, uses an isolated local domain fixture and records the read, gesture and acknowledged result. Creating or testing a reducer without wiring its UI cannot certify the node. A root whose backend seam is missing receives a new dependency node before implementation; a permanently disabled action is not a replacement for an existing supported workflow.

G00 creates the runner and failure checks; G03 extends the existing runtime witness/report plumbing. Thereafter each builder supplies its own tests and witness expectations. The integrator alone wires them into shared registries and runtime dispatch. G01 is a module/feature proof with no claim of a running UI; G01H supplies the actual CEF-free host, G01P its default launch/package, and G01D its native report and exclusion profile before normal workflow witnesses begin. Fixtures may stand in for unavailable external parties, but not for the production UI/domain path being claimed. Human visual judgment is separately recorded at G28/G29, not inferred from counters.

Dependencies require `certified`, not merely a merged branch. The states are `planned`, `claimed`, `in-review`, `merged`, `certified`, `blocked` and `stale`. On each merge, re-prove the accumulated certified set on that tree; if it regresses, stop dependent dispatch. A changed shared contract invalidates affected certificates until they pass again. Full three-repeat benchmarking belongs to G29; per-node runtime smoke witnesses are not substituted for it.

## Exclusive measurement protocol

The planner stops dispatch and requests a pause from every run worker, including integration. Each worker reports its live process groups and acknowledges that compilation, tests, apps and background jobs are drained or safely cancelled. Sending a pause message is not proof of an idle machine. The inspector verifies the run-owned processes, obtains the machine/GPU/display/fixture lease, records outside load and freezes source changes in the measured tree. It prepares the release binary before sampling, warms up, records the reports and checks their revision and workload before releasing the lease. Workers resume only after release. Unexpected load invalidates the sample; unrelated user processes are never killed by this plan.

## Builder brief

Every dispatch names the node, absolute checkout/branch, certified dependency revisions, exact owned files, selected Corgi feature set, required tests, source behavior references and role-packet path. It includes the Part A decisions above, relevant Sand contract, the wider Box identity/ownership constraints and explicit exclusions, not the entire planning conversation. It states the owner's worktree permission while AGENTS/CLAUDE and `.lingua` remain uneditable, that code comments are prohibited by the project, and that licensed embedded dependencies carry their notices in the owning Sand. Every role follows the context-resume checks, including the planner and combined verifier.

Builders run the narrow check during editing; when the proof is a test, run that test rather than paying for a redundant check immediately before it. They do not run CEF, joined apps, benchmarks or production-domain mutations. Both Corgi-suitable and explicitly assigned native Cargo/Nix work follow [the build lanes](build.md#which-tool-does-which-work); a compiler choice never changes Part A's CEF-free feature set. They report node id, command/output, files changed, commit/revision, test/witness coverage and requested edits outside ownership. An unrun exclusive proof is reported as unrun, never as passed. The integrator performs shared edits and accumulated re-proving; the inspector separately checks spec drift and exclusive evidence. Only the planner marks a node certified and releases its dependents.
