# Calendar, Clock and simulation

Calendar shows time-related Record properties inside a Castle of ordinary navigation and editing controls. Start with agenda, day, week and linear timeline views. A person selects a Protein and maps the title, Record reference and date fields.

An instant is a point and an interval occupies a strip. Date-only work belongs in an all-day lane; undated work has an unscheduled list. Overlaps remain selectable. Invalid dates and unavailable values explain themselves. Keep result counts bounded and preserve selection when the visible period changes.

Recurring entries come from Karma's occurrence projection. Repeated appearances do not create Records or run a Rule. Timezones, daylight-saving changes and schedule edits follow the backend's rules. Dragging a date previews an ordinary Action, with a keyboard equivalent. Offer one-occurrence or whole-series edits only when supported. Quantity forecast buckets are not appointments.

The Clock uses those same entries. From above it shows the rolling next hour; perspective reveals a spiral with a chosen future horizon. An initial turn represents an hour. Intervals can cross turns while keeping one identity, and each recurrence has its own appearance. Later turns are explicitly filtered out of the top view.

Overdue unfinished work remains visible after leaving the live strip. Holding the displayed time is clearly labelled and has Return to now; it does not pause Karma. Keep an accessible agenda and use discrete updates for reduced motion. These time views need no Box terrain or general physics.

Simulation compares a proposed Action, Rule or Transfer with current state. Show the scenario's starting revision, time, assumptions, changed fields and reasons, including changes outside the current view. Keep observed, scheduled and simulated information distinguishable.

A preview needs real permission-filtered backend support. It must name unknown consequences and produce no real Facts, messages or external effects. Applying a proposal rechecks current data and uses ordinary Actions; partial application is available only where dependencies can be preserved. Calendar and Clock remain useful before simulation exists.
