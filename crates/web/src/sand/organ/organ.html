    Your pairing code

    Show this code to someone in person, or paste it into a chat app you already trust. Both are safe for the same reason: nobody can sit in the middle of a code you hand over face to face, or of a conversation that is already proven to be them. It carries the address you are reachable at, so an in-person scan works even on wifi that blocks local discovery.

    Your published key

    This is what someone saves to reach you, and it stays the same across every device change. Safe to put on a website: on its own it is an identifier, and it grants nothing. Handing it over in person, or pasting it into a chat app you already trust, is what makes first contact safe — neither channel can be relayed by someone in the middle.

    The root key signs only two things: your device list and key rotations. Everything routine uses a per-device key instead. Keeping the root off this machine is the point — then a stolen or broken-into device costs one revocable credential, not your identity. Copy it to removable media, verify, then remove it here. Enrolling or revoking a device will ask for it back; nothing else changes.

    Removing is only safe once the copy is verified. Detach checks the copy byte-for-byte first, because there is no authority anywhere that can restore a lost root key.

      The name beside each row is what that Cell calls itself — a claim, not a verified identity. The short code next to it comes from the key itself and cannot be faked by choosing a name, so use it to tell two rows apart. It is a way to find the right row, not a security check.

      Add someone by code

      Adding by code trusts it on sight — Lince has no way to check that a pasted code really belongs to who you think, so where you got it from is the whole of the security. From their hands or from a chat you already trust: safe. Forwarded by someone else, or found somewhere public: not. The name is yours to choose and is never taken from the code.

      Devices
        This device list has expired. Contacts keep using the last one they saw, and no new device can join until it is signed again.

        Adding a device is pairing with yourself, so it gets its own one-time code rather than reusing a contact invite — this code grants membership in your identity, which is strictly more. It works once and expires in ten minutes.

        Removing a device from this list is the revocation. Contacts accept only a newer list than the one they hold, so an old list cannot be replayed to put a stolen device back.

        Locally online advertises this Cell over mDNS and listens for other Lince Cells on this LAN. It does not make unknown Organs trusted or allow them to open a conversation.

        Reachable over the internet publishes this Cell's address so contacts can find it from anywhere — that is what lets an always-on Cell tell your phone about a change your laptop made. Turning it off keeps you findable only where a direct path already exists. What it costs when on: anyone holding your published key can resolve your current address, which reveals roughly where you are and when you are online. Nobody can read your data or forge your signature either way.

        Accept chat requests from unknown Organs is OFF by default. While it is off, publishing your key advertises reachability to people who already know you and grants nothing to anyone else — a stranger you meet on the network cannot open a thread with you, so the nearby list will refuse everyone. Turn it on to let first contact happen.

        Changing reachability rebinds the connection endpoint. Your Organ key and NodeId do not change, so saved contacts stay valid.

        Every plain record whose origin is this organ mirrors to a markdown file here — head is the filename, body is the file's content. Editing a file's content updates the record; deleting a file (after two consecutive misses, to survive an editor's atomic save) deletes the record; a new file becomes a new record. Picking exactly which records sync — beyond "belongs to this organ" — is a Protein filter, and it's future work, not wired up here yet.
