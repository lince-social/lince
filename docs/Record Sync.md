e can also do a sync of a Record to another with 's' followed by 'n' to grab the original Record itself and/or 't' for the tree of Records that spring from it (the "children" you could say).

So let's say we want to copy the original Record and its children to another, the could would become 'snt'. Then we choose if we want to sync the quantity 'q', head 'h' and body 'b'.

If we are on the Trail feature of the Web Interface we want to copy a personalized Record and it's tree as our personal trail. We want to sync the head and body of the tree nodes to maintain the theory, but make quantity be independent in the copied tree so we can set the state of our trail in a personalized way. The final code would be 'snthb(Id)'. That's why we deal with it in a graphical way.

*Example*

Condition: snthb1
Operator: = (in this case doesn't matter)
Consequence: snthb2
