# Fiote workflow acceptance tests

Workflow under acceptance: download/import supported English ASR → select/check microphone → record at least three local “Hey Fiote” examples or import a compatible reference → optionally install a local decision model and enable destination routing → explicitly enable listening → give a combined or separate wake/request → appropriate Fiote or parent delegation → normal conversation, verified action and optional spoken reply → further speech without repeating the wake phrase. The first request chooses a destination; accepted follow-ups retain that Fiote, thread, history and normal permissions. A separate tool-free classification uses the last request/reply to distinguish continued requests, corrections and short answers from closing remarks, speech to other people, quotations and uncertainty. Ending or ninety idle seconds re-arms activation. Explicit End voice conversation also clears the binding; Stop listening keeps capture off.

Implementation and regression tests are written. Test execution is awaiting the user's later approval; do not execute this checklist yet. `cargo check --tests` checks compilation and does not establish runtime acceptance. Remove tasks only after their tests have actually passed.

Local routing is available experimentally; it is not an accuracy claim. Ambient listening without any first activation still requires separately validated admission. Follow-up classification uses an installed local model, or the selected Fiote's native provider when local inference is unavailable/fails. A local abstention does not trigger a second, more permissive judgment. Native fallback sends the transcript and bounded recent context to that provider and consumes its normal quota; no tools are exposed and no Message/action is created by classification. Unsupported connections, malformed answers, low confidence, cancellation or timeout re-arm activation without dispatch. No classifier guarantees perfect understanding of human intent; measure false acceptance and premature endings before relying on hands-free actions.

Test Kokoro voice setup separately from Phonon-2 transcription setup; arbitrary model files are not supported. Model installation must never start capture automatically. Use the native provider connection without a required external harness.

Run these in order using the native Rust controls/Laboratory and the Nix interface shell. Keep fixture, real-model, OS-monitor, physical-device, authenticated-provider and packaged-binary results separate. Preserve logs and failed references; an ignored or interrupted case is not a pass. Use isolated data and a disposable working directory for actions. Record source/binary identity, selected model/assets and result artifacts, without credentials or private conversation content.
