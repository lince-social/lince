## Scope and ownership

Keep Smithay and Rust. Reuse its device, session, output, input, surface, layer, selection, lock, and rendering machinery. Park owns the adapter to Lince's Bevy/wgpu canvas and Lince's placement, Area, workspace, focus, and lifecycle decisions. Do not introduce another window-management model beside the canvas.

Users choose the login/session manager, launcher, bars, notification service, tray, audio/network controls, locker, IME, clipboard manager, and portal backends. Park must not implement replacements or install/start them automatically. Local literal executable/argument targets and protocol adapters are enough where a concrete capability requires them. Synchronized Records do not authorize process execution. Listing a possible external tool does not promise every one of its modules will work.

Keep native Wayland programs and one selected graphics device as the hardware target. The active work extends output modes, placement, scaling, and input capabilities below. XWayland and browser-specific integration stay out of scope. Test the user's existing tools first, while implementing general protocol contracts. Their executable names, configuration paths, and compositor-specific IPC must not become Park policies.

Reactive reconstraining itself already exists in `server/popups.rs`; retain only its missing edge-case verification here. Implement explicit modality only when supported by a selected protocol and covered by a focused regression. Parenthood does not itself mean modality. ## 4. Laboratory isolation

Laboratory still pauses native Cell consumers and services globally. Ordinary native content on another output can therefore stop updating during Laboratory work. Replace that global pause with isolation of the temporary benchmark content.

This requires reviewing the global contract across Cell dispatch, Record subscriptions, practice routing, timers, media, and mutation guards. Removing only `cell_bridge::drain`'s pause lets messages expire while consumers remain paused. Proceed in this order:

1. Audit producers and consumers together in `native/cell_bridge.rs`, `practice_cells.rs`, `laboratory/workspace.rs`, Record binding/view code, `time_limit.rs`, `time_castle/`, `video_castle.rs`, and all uses of `laboratory::normal`/`active`.
2. Give temporary benchmark content an explicit owner/source boundary. Keep ordinary owners' subscriptions, timers, and media running; prevent temporary content from reading or mutating ordinary Records. Reuse practice/test routing rather than another real Cell or desktop.
3. Extend cleanup to any new owner-scoped subscriptions/resources using the existing Laboratory lifecycle. Verify temporary work leaves no save, placeholder, or subscription and that ordinary client windows survive restoration.
4. Add a regression with Laboratory on one output and live ordinary native content on another. Verify both background progress and denied cross-owner mutation. Preserve Sandbox Laboratory behavior.

Park's separate logout/bootstrap and restart-dependent update/backup handling must remain intact while this is changed. Storage maintenance needs explicit logout; it must not implicitly stop or restart the active desktop.

## 5. General external-tool adapters

These adapters are active scope. Their external applications and services remain user-selected. Test the existing setup first and prove the contract with an independent protocol client so compatibility is not inferred from one program's behavior.

1. **Shared helper authorization.** Extend the existing local launch/socket and client-data mechanisms for explicitly authorized privileged helpers. Capabilities belong to specific connections and local configuration, never synchronized Records, titles, or spoofable app IDs. Prefer an inherited connected Wayland socket for helpers launched through Park; keep ordinary client connections unprivileged. Reuse this binding for clipboard history, input-method control, capture, and privileged management as needed. Accommodate the selected external supervisor through a narrow handoff; do not create another daemon or autostart framework.
2. **Window listing and control.** Use Smithay's foreign-toplevel listing helper for map/unmap, title/app-ID, output, and lifecycle updates. Add the standard management/workspace capabilities required by general taskbar tools through a maintained helper or thin adapter, routing actions through Lince's existing desktop policy. Keep listing and management authorization distinct, validate activation/focus requests, and remove handles on destruction. Test the relevant Noctalia modules first, then an independent standards-based consumer. Do not implement Niri/Sway/Hyprland IPC to make a test pass.
3. **External clipboard history.** Bind an explicitly chosen history process to privileged data-control access. Verify Unicode text and supported MIME transfers, focus/selection changes, helper restart/disconnect, and denial to unrelated clients. Keep clipboard storage/history and its UI in the external program. Preserve the existing native clipboard connection.
4. **Screenshot and screen sharing.** First resolve the maintained compositor helper/protocol combination and external portal backend, then implement only Park's capture/export and authorization boundary. Prefer standard image-copy capture/source protocols where the selected backend supports them; add a compatibility adapter only for a demonstrated general-tool requirement. Capture output or selected window content with correct transforms, clipping, cursor policy, buffer lifetime, and damage. Honor the portal/provider's consent and selection flow. Stop or protect capture on lock and handle hotplug, source destruction, cancellation, and helper death. Reuse the existing portal and PipeWire implementations; do not write either service or a custom picker.
5. **Output-control integration.** Connect the output configuration from section 3 to the standard protocol needed by a selected output tool. Validate and apply a complete configuration transactionally; reject unsupported requests without changing the active layout. Test mode, position, scale, enable/disable, rollback, and stable connector/workspace identity. Keep output profiles and settings UI in the external tool.

The pinned Smithay 0.7 sources have helpers for fractional scale, text input/input method, relative pointer, constraints, inhibitors, and read-only foreign-toplevel listing. Do not assume current online Smithay documentation matches that pinned version. Before adding capture/output-management/toplevel-management machinery, audit the required API and maintained libraries. Prefer a bounded, pinned Smithay/helper update when it avoids a substantial protocol implementation; rerun the affected session, server, and Sandbox checks for that dependency change.

Portal/window-management providers can require protocols or compositor-private APIs that other providers do not. Record each tested provider/module and its supported capability. General support means implementing documented protocol contracts with real behavior; it does not promise every third-party module works unchanged.

Login, autostart supervision, bars, launchers, notifications, tray, password UI, IME engines, clipboard-history storage, portal services, application catalogs, and system settings remain external responsibilities. Only their necessary compositor bindings are part of this round.
