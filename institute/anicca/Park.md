Future work is tracked separately in [Park–Spacematter integration](Park-Spacematter.md) and the [retained deferred backlog](Park-deferred.md).

## Remaining work

Run in order after execution is authorized. Each item includes corrections exposed by its checks; there is no evidence yet that a new general desktop subsystem must be built.

- [ ] **Automated and nested acceptance while staying in Niri.** Use the existing `cargo xtask park ci` and validation preparation, plus native-client/worker probes where not covered. Check Park and Sandbox with warnings denied and `cargo check`, never `cargo build`; Cell-backed checks need `RUST_MIN_STACK=33554432`. Run authored protocol/layout/input/drop/IME/constraint/idle/Laboratory regressions, delayed-GPU/resource-lifetime tests, selected-window pixel export and two-output nested/capture smoke. Verify controls, persistence/logout, paired snapshots, client lifecycle and isolation. Use repeated lifecycle/soak fixtures to measure idle activity, responsiveness and CPU/GPU memory/descriptors. Keep disposable data/profiles. Source/tooling: `crates/xtask/src/park{.rs,/validation.rs}`, Park probes/server tests and interface layout/Laboratory regressions.
- [ ] **Real external-provider compatibility.** Test the user's native terminal/browser and applicable Noctalia modules first, then the selected bar/launcher, IME, clipboard history, locker, output-control and portal/PipeWire providers. Verify connection capabilities and the chosen supervisor's FD/readiness/restart behavior, ordinary-client denial, menus/reservations, window/workspace control and capture consent/cursor/resize/disconnect behavior. Independent protocol clients already provide the second implementation check. Record versions and unsupported modules; add a binding only for a demonstrated missing general contract. Keep services/UI/storage external and Niri's service environment untouched.
- [ ] **Physical presentation, protection and recovery.** After nested gates pass, use the existing prepared TTY runner while retaining Niri. Verify actual scanout/input, default/rebound commands, multiple outputs/scales/modes, transactional rejection/rollback, connector removal/reconnect including the last output, VT return and suspend/wake. Verify lock protection on every output, locker disconnect/hotplug and blocked ordinary input/capture. Check Operation activation against the same directory, survival after the last client closes, save-aware logout and reopen. User actions are foreground TTY login, physical input/visual observations, passwords/consent, cable changes and wake. The agent runs probes, collects reports/diagnostics and investigates failures; watchdog exits do not count as success.
- [ ] **Installed session and daily-use acceptance.** Validate the existing Nix package/module and separate CI artifact: runtime libraries, installed paths, session entry and licenses. Review the prepared personal configuration against the intended source/tree, preserving Niri/default session and existing Cell directory ownership. After separately authorized activation, test one clean display-manager login, selected service startup/teardown, locking/recovery and a representative longer work session with required native Wayland applications. Record X11-only limitations and resource behavior before recommending daily use. Packaging, workflow and proposal source already exist; do not recreate them.
