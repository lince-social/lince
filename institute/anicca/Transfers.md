## Focused automated checks

- [ ] **E1 — Place search and routing.** Run the two cases in `crates/map/tests/navigation.rs`. Verify bounded offline place search/reverse lookup; selecting a result changes selection only, with saving left to normal Record controls. Exercise the local HTTP routing fixture, decoded coordinates/mode/time estimate, explicit request permission, configurable rate limit and invalid provider URLs. Old replies cannot replace a newer selection/route, and cancelling/invalidation clears geometry. No public map service is contacted by these tests. Exact private Record coordinates must never be fetched merely to make a provider request; providers receive only the reviewed visible points.
- [ ] **E2 — Stops as parts of a larger Transfer.** Run the three new cases in `crates/nucleus/src/transfer/transport.rs`, `crates/interface/src/transfers/transport.rs` and `crates/engine/tests/transport_journey.rs`. With one seat on A–B–C, permit A–B and B–C contributions and reject overlapping A–C occupancy. Each part must be a normal linked Transfer draft with independent terms and confirmation. Finishing one part releases only its capacity and preserves the other part's progress; no settlement, receipt or experience is synthesized from an aggregate journey. Reuse existing journey-linked sharing/Stop coverage for per-person, per-Transfer boundaries.
- [ ] **E3 — Regional packages.** Run `regional_preparation_reuses_normalization_and_preserves_existing_packs_on_failure` in `crates/map/tests/offline_map/packs.rs`, together with the existing corrupt/oversized/interrupted-import contracts. Require deterministic normalized tiles and manifest hashes, no building layer, source/license/credits, bounded coverage/zoom/size, and a usable previous pack after failure/cancellation. Verify preparation publishes only a finished pack and never overwrites an existing destination. Do not repeat unchanged PMTiles/directory reader matrices.
- [ ] **E4 — Typed trust and supplier selection.** Run the two new category/source-policy cases in `crates/nucleus/src/trust_analysis/claims/tests.rs`, the credential-form case in `crates/mobile/src/workflows/tests.rs`, the supplier case in `crates/engine/tests/transfer_evidence.rs` and the structured-choice case in `crates/interface/src/transfers/matching.rs`. Require activity-specific issuer choice, validity/withdrawal/exclusions winning, no recommendation or credential added to delivered quantities, and stale/unlisted Need choices rejected. Matching must use the receiver-authored Need's exact meaning/unit, visible available offers, time/optional geographic constraints and reader filters/weights. Repeated search changes no transfer state; a disappeared offer is not silently replaced or executed. A chosen candidate proceeds through ordinary reviewed Transfer controls.
- [ ] **Migration guard.** Run the existing `migration_guard` tests after approval. Migration `0038_retire_stock_policies.sql` cancels queued stock effects and disables obsolete generated rules. Verify its appended checksum and that every previous migration/checksum entry remains unchanged. `cargo check -p store` is the compilation check, not a substitute for running the guard tests.
- [ ] **Bounded workflow regression.** Reuse the existing two four-Lince scenarios in `crates/simulation/tests/location_visibility.rs` and the native `four_lince_transport_control_draft_finishes_sharing_before_later_settlement` case. Cover a map-free Transfer, an `#address` reference, user-configured approximate area, exact/area-only/excluded audiences, and independent Finish/Stop before settlement. Reuse the existing four-Lince trust publication/correction case where changed claim serialization or serving requires it. No whole-Laboratory rerun, map-resizing campaign or larger topology.
