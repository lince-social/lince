[Organization and execution order](Park.md). Targets are in [benchmarks](08-benchmarks.md); interaction coverage is in [workflows](09-workflows.md).

Measure command-to-effect latency first, including native typing and local Record saving. Existing counters/timing histograms and the private renderer fixtures are reusable; add only the missing causal links. An observation of high CPU or a stage's elapsed duration is not attribution of user-visible delay. P103 completed the [fixture definition](workloads.json) and current runtime/source identity manifest; P101 has added and checked native/client correlation; trace local edit/save phases next, then rank causes. Mixed-scene adapters and actual daily counts are explicitly still pending under their implementation/inventory tasks. The same trace serves scheduling, storage, style and GPU questions.

- [ ] **P102 — Trace one local Record edit through durability and view publication.**

    **Why:** a title/description save currently has several possible amplification and wait boundaries. **Scope:** on a private synthetic local Record, correlate editor revision, draft preparation/encoding, draft-write queue/acquire/commit, ChangeRecord admission, access scope, canonical transaction, acknowledgement, query/collaboration refresh, affected-view update and visible presentation. Count SQL statements, transaction/fsync boundaries where observable, snapshots/bytes, clones, query executions and views touched. Measure head and body separately at 1 KiB/64 KiB/1 MiB body sizes and one versus eight views. **Close with:** a critical-path/work-amplification report distinguishing immediate echo, durable recovery, canonical save, publication and remote sync, with no network dependency on the local baseline. A blocked writer scenario is a correctness probe, not the normal latency result. **Feeds:** stage 3; use actual file-backed storage for durability costs.

    **Established baseline:** input correlation, borrowed editor reads/splicing, incremental recovery and trusted accepted-history reuse are already measured in 00. The existing opt-in reporter covers binding updates, draft queue/write, access/import gates, admission, candidate/history work, canonical begin/body/commit, observation/reactions and query/refresh spans. P118 removes unrelated subscriptions; completed P126 removes unrequested result preparation and measures SQLx completions with a private tracer. Actual fsync captures exist for the earlier populated-subscription comparison. Reuse these signals and source-stamped executables rather than building another profiler or repeating completed counts.

    **First next local measurement:** separate the large non-query remainder of a native refresh. P126's four native cases total 5/177/14/97 ms in query execution versus 436/228/251/157 ms in refresh. Inspect/time existing SyncService::run and sync_activity::append boundaries, queue/acquisition, durable commit and required status publication; correlate each operation before assigning the gap. Preserve required history entries, ordering, completion/error reporting and durability. Removing logs or changing synchronous policy is not a valid shortcut. This attribution can promote the corresponding store/queue task immediately without waiting for every missing trace field.

    **Still required for closure:** production per-edit causal identity through the now-timed backend phases; actual SQLite statement accounting beyond logged SQLx invocations where observable; CPU versus wait per edit; graphical bytes/entity churn, publication and visible presentation; and complete S4 adapter coverage at 1 KiB/64 KiB/1 MiB with one/eight views and distinct-Record controls. Awaited spans overlap and cannot be added as CPU time. Keep tracing-off controls, blocked-writer correctness, exact cold reopen and truthful recovery/canonical completion boundaries. The high-entropy edit diagnostic and read-only Unicode query probe differ from the frozen S4 paragraph recipe. Larger setup uses the supported text-edit API around CreateRecord's separate 256 KiB limit; do not weaken guards. Current optimized daily/physical attribution remains P66/P65.

    **Evidence:** 00 links local-edits/, accepted-history/, incremental-recovery/, borrowed-splice/, query-invalidation/ and query-projection/ receipts under target/park-validation/performance-20261105/. The last two preserve populated query/history semantics, mixed acknowledgement/full-query controls and all initial failures. - [ ] **P67 — Map CPU/GPU responsibilities across the active frame path.**
