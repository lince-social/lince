# 3. Make local editing and saving immediate

[Organization and execution order](Park.md). Targets are in [benchmarks](08-benchmarks.md); interaction coverage is in [workflows](09-workflows.md).

Treat title/description editing as a full local workflow. The user's report is that saves feel remote despite local storage. Current evidence establishes expensive possible work, not its current timing: TextBinding exports/encodes a draft on the foreground thread, writes it asynchronously, and gates canonical send on the saved revision; Cell handles ordinary session requests inline; description preview changes rebuild most children. Profile-save JSON already has a background writer and must not be confused with Record text/draft SQL. Start with P102's report, and investigate the separately reported database-lock issue before changing the implicated lock boundary.

Preserve immediate draft text, durable recovery, canonical local commit, publication and remote sync as distinct states. Local input must not wait for network acknowledgement. Do not replace durability with a longer debounce alone. Reuse the existing Record mutation, Loro and storage families. Every write experiment must test actual file-backed reopen/recovery, not only an in-memory database. Source anchors: native/record_binding.rs, record_view.rs, description.rs, protein_area; native/cell_bridge.rs; crates/transport/src/session.rs; engine/record_change.rs and store/record_docs.rs.

- [ ] **P94 — Identify the cause of the database-locked toast.**

    **Why:** contention may stall operations or expose a correctness failure independently of rendering speed. **Scope:** attribute one occurrence to the responsible database/operation and transaction/connection lifetime, using bounded logs without private values. **Close with:** the cause and one concrete fix target, or an explicit missing reproduction. Do not assume it is the FPS cause, increase timeouts to hide it, relax durability, or alter existing migrations. A subsequent implementation gets its own atomic task once its mechanism is known.

- [ ] **P137 — Remove one document-sized cost from canonical text mutation preparation.**

    **Why:** recovery draft encoding is not the only whole-document path. AcceptedDoc/prepare_delta imports the retained snapshot and prepares a guarded candidate; persist_text updates both head/body, counts the durable delta tail and periodically checkpoints it. **Scope:** use P102 to isolate the dominant snapshot import/export, candidate validation, full-field projection or tail-query cost, then compare one revision-stamped incremental alternative. The canonical path already has sync_op deltas and COMPACT_OPS = 100; do not replace it with another journal or claim it snapshots to SQL on every edit. **Verify:** accepted/rejected malicious and malformed deltas, limits/history/permissions, conflict/undo, idempotent receipts, checkpoint boundaries, stale candidates and exact durable reconstruction. Preserve the guard's isolation and atomic validation; reuse trusted state only under its valid revision/ownership. Measure whole caller/worker/transaction cost and bytes at S4 sizes, not just a faster export function. **Needs:** P102; distinct from the frontend recovery draft in P114/P115.

    **Concrete lead from P102:** the private 1 MiB public text-edit setup exceeded 180 seconds in the diagnostic build. Two bounded debugger captures found loro_internal::InsertSet::update_many at richtext/tracker/id_to_cursor.rs:465, reached through JSON import, collab_guard::import_complete, prepare_delta and prepare_text; SQL workers were idle. First establish a minimal matched optimized reproduction and distinguish bulk setup from a one-character edit on an existing large document. Do not weaken permission/history validation, silently replace JSON with unchecked binary import, change machine profiling permissions or infer release behavior from this debug result. Raw captures and the timed-out fixture are in local-edits/. Kernel perf sampling was unavailable; the debugger traced only private child processes.

- [ ] **P114 — Persist recoverable text edits incrementally instead of full snapshots per edit.**

    **Why:** TextBinding exports a Loro snapshot plus pending requests before permitting the canonical change; repeated document-sized work can amplify every keystroke. **Scope:** compare an incremental recoverable journal of existing operation/update identities plus periodic snapshot against the current draft representation. Reuse existing engine record_change/record_docs mechanisms where they already cover the needed data; do not introduce a competing history store. Keep durable-before-send intent where currently required, or prove a replacement atomic local transaction that covers both responsibilities. **Verify:** crash/reopen at each append/commit/ack/compaction boundary, exactly-once/idempotent replay, collaboration/undo/IME, failed/denied edits and remote pending intent. Measure foreground CPU/bytes, writes and latency by document size. Any schema change is a new guarded append-only migration. **Needs:** P102; never trade away truthful saved/recoverable state.

- [ ] **P138 — Shorten the engine-wide access gate without weakening operation validity.**

    **Why:** Engine::access_scope holds a shared read/exclusive write RwLock across the awaited operation, so a write can delay unrelated reads/writes despite spare CPU; nested scopes deliberately reuse the held task-local authority. **Scope:** after P102 attributes gate wait/hold, select one long pure or post-commit phase that can safely leave the gate, or compare a narrower validated generation boundary. Retain atomic permission/revocation, reentrancy, operation ordering and all transaction invariants. Do not add unsafe cached grants, clone a held task-local scope into independent work, or remove the lock as a blind parallelism switch. **Verify:** simultaneous local edits/queries, revocation and session expiry racing preparation/commit, nested actions, cancellation/failure and deterministic final state. Include conflict/revalidation cost and actual wait reduction. **Separate from:** P117's database transaction and P121's Cell request queue; those can serialize independently.

- [ ] **P139 — Remove unnecessary post-commit reaction waiting from local save feedback.**

    **Why:** observe_committed_fact publishes the committed fact and awaits react_to_event; local edit paths can await this before returning while still within access_scope. Slow rules/effects can therefore make a committed local edit appear unfinished. **Scope:** measure required versus deferrable post-commit work, then expose truthful local durable completion independently or use an existing recoverable ordered effect queue for the selected deferrable family. If the action contract requires reaction completion, keep that separate status and preserve its semantics instead of falsely returning full success. **Verify:** saved text, facts/history, rule ordering, exactly-once/idempotent effects, crash/restart, effect failure, cancellation and visibility of pending/failed reactions. Do not detach unbounded tasks, lose required automation, or create a new outbox if one already fulfills the contract. Include acknowledgement and other-input p95/p99 plus total work. **Needs:** P102 and the P138 scope analysis; reject decoupling where semantics require the wait.

- [ ] **P121 — Prevent a slow Cell request from delaying unrelated local edit service.**

    **Why:** the Cell bridge selects requests but awaits ordinary session.handle requests inline; a long request can delay the shared lane despite a multithread runtime. **Scope:** use P102 to identify one long request class, then separate its pure/blocking preparation or provide bounded existing-pool execution while preserving session state, per-Record ordering, access scope and transactional command semantics. Special call/speech/preview task lanes already exist; do not reproduce them or spawn every request independently. **Verify:** local edit/ack and cancellation during the slow request, fairness, session expiry/revocation, failure and bounded pending work. Include shared database lock pressure, because concurrent tasks alone may still serialize on a writer. **Conditional on:** measured head-of-line delay; no claim that the source shape alone proves the live cause.

- [ ] **P117 — Shorten the measured SQL transaction critical section for an edit.**

    **Why:** local writes can still wait behind connection acquisition, broad access snapshots, repeated queries or long transactions. **Scope:** select the dominant P102/P94 database acquire/hold/commit stage in engine record_change/access or store; P138 separately owns the engine-wide access gate. Move safe pure preparation outside its mutable transaction, reuse transaction-local reads or remove a proven duplicate query while keeping authorization, facts/revisions and atomic commit valid at the operation boundary. Inspect file-backed WAL/checkpoint and pool behavior; additional SQLite connections do not create multiple concurrent writers. **Verify:** contention with background work, access revocation, rollback, lock errors, replay and durable reopen. Record acquire/hold/commit separately and use query plans before proposing an index. Raising busy_timeout or weakening synchronous durability is not the fix. **One concrete critical section per experiment.**

- [ ] **P118 — Limit one local edit notification to actually dependent subscriptions.**

    **Why:** a small Record edit may fan out to repeated full query snapshots and many presentation rebuilds. **Scope:** trace on_sync_event/refresh and protein_area/Record views, then narrow one measured notification family through existing source/Record/property/query dependencies and retained row identity. Coalesce compatible invalidations and publish row/delta updates where supported; retain a conservative full refresh when dependency knowledge is incomplete. **Verify:** edits that change sort/filter/group membership, quantity/assertions, deletion, query/source replacement, remote changes, access revocation and multiple views. Count queries, rows/bytes and rebuilt entities per edit, including the cost of dependency tracking. Do not cache access grants or suppress necessary remote/backend semantics. **Needs:** P102; current retained presentation caches remain the baseline, not work to rebuild.

- [ ] **P119 — Update a description preview incrementally while typing.**

    **Why:** description::sync_editors reads whole editor strings and set despawns non-shader children before markup::render on source changes. This can couple typing to full preview construction. **Scope:** preserve unchanged parsed blocks and entities for one description-edit path, applying only affected text/markup/assets and retaining the latest revision. Compare a bounded deferred expensive preview against synchronous patching where warranted; raw editor feedback must remain immediate and Pretty/Split must converge promptly. Reuse existing shader/media/transclusion lifetimes. **Verify:** paragraph edits, cross-block syntax, links/images/diagrams, shader preservation, raw/pretty/split switches, selection/scroll, errors and close during work. Count parse bytes, entities churned, allocations and latency for small/large documents. Do not silently disable previews or rebuild all content on every cursor move. **Needs:** P102; no second general text renderer.

- [ ] **P115 — Move unavoidable recovery snapshot encoding off the interaction thread.**

    **Why:** snapshot export, base64 and JSON preparation currently occur before the asynchronous storage task, so asynchronous SQL alone does not remove foreground work. **Scope:** after P114, select the remaining necessary checkpoint/snapshot operation and compare immutable revision-stamped worker preparation with the serial path, including snapshot/input capture cost. Respect Loro ownership/Send constraints; do not mutate the live document from a worker or clone its full state on every key to claim success. Coalesce only superseded checkpoints covered by a durable journal and bound one active plus pending work. **Verify:** current-revision acknowledgement, errors/retry, shutdown flush, removal and edit-during-compaction recovery. Measure the complete caller plus worker cost and foreground p99. **Conditional:** omit/discard if incremental encoding already makes this negligible.

- [ ] **P116 — Amortize one stream of local edit commits without delaying feedback.**

    **Why:** one draft/canonical transaction per character or view can multiply durable I/O and backend effects. **Scope:** use P102's write counts to batch compatible pending changes for one local document within a bounded latency window, preserving individual operation IDs, ordering, conflict and undo/history semantics. A canonical transaction may absorb recovery work only if it provides the same recoverability. Keep local echo immediate and explicit save/close/flush as real barriers; do not merge distinct commands, assertions, counter deltas or auditable side effects merely because they are adjacent. **Verify:** concurrent views, typing while a write is blocked, rapid edits then close, failure/replay and bounded journal age. Include p95/p99 durability and effects, not just commits/second. **Needs:** P114 and honest status boundaries.

- [ ] **P123 — Remove one whole-text reconstruction from ordinary editor updates.**

    **Why:** repeated value().to_string, equality/diff, selection-anchor and preview scans can make a single key cost proportional to full document length and open views. **Scope:** profile the current text/edit binding path, then use an existing edit revision/delta or borrowed representation at one repeated reconstruction site. Preserve Unicode/grapheme/IME, Loro cursor/undo, pending-paste and multi-view semantics; the existing text shaping cache is already implemented. **Verify:** empty/title/large body, selection-only moves, one-character changes at either end, paste and remote merges; count copied/compared bytes and foreground CPU. Do not add a parallel second text cache or convert cheap edit deltas back into full strings at every consumer. **Coordinate:** P79 retains structured Record views; this task is specifically editor text materialization.

    **Implemented:** selection now borrows the current text already materialized by the binding loop, avoiding one full string allocation/copy per bound view and update. No second text cache was added. Unicode/reversed selections, remote insertion, composition, undo, shared views, unsent draft recovery and the native stable-selection case passed. The 1 KiB/64 KiB private matrix and tracing-off controls completed; wall-time improvement remains unresolved. **Before closing:** finish the remaining empty/large-bound-editor coverage with the reusable fixture; the 1 MiB path is currently blocked before binding by P137's canonical import cost. Keep the code and this explicit validation remainder.

    **Why:** cloning or re-projecting unchanged structured data can consume CPU across many interface items. **Scope:** select one residual path in record_binding/protein_area/custom presentation from P66; use current typed views or source revisions and the existing retained-row infrastructure. **Verify:** same-tick edits, source/UID replacement, deletion/reload, dirty drafts, permissions and row removal. Compare both steady and constantly changing data and bound retained memory. The existing Record-presentation cache is already implemented; a whole-interface serde rewrite is not this task.

- [ ] **P120 — Eliminate one proven no-op edit write and its downstream publication.**

    **Why:** focus changes, acknowledgements or unchanged serialized state can repeat writes and invalidations without changing the document. **Scope:** choose one actual path from P102, compare canonical revision/value at the correct boundary, and skip only its redundant encoding/SQL/event.
