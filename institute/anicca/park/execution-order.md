# Execution order: tooling first, broad measured fixes, one candidate

[Organizer](Park.md), [required workflow](12-measurement-and-delivery.md). This is the single cross-file queue. It orders coding inside a broad cycle, not one task per turn/build. Every P ID has one checkbox definition; completed work stays in [00](00-evidence-and-research.md) and authorized rejected outcomes in the [Build museum](../../trails/lince/Build.lingua).

**A0:** code all ready measurement/suite/delivery work first, push and stop, then establish the detailed installed baseline. **A1:** use that evidence to code all ready independent Stage A fixes together. Use one coherent optimization mechanism per measured owner per cycle, with necessary supporting edits and named collateral effects. **A2:** evaluate all coded work with one ordered combined suite on the new binary, close verified tasks and use the report for the next broad cycle. A task needing a binary is not a reason to stop other ready coding. There is no fixed batch-size cap.

**No local Rust compilation:** cargo check/test/build, compiling xtask commands and Nix builds are excluded. Use available static checks and already-built artifacts. CI checks/builds matching application and validation artifacts with warnings as errors. At the completed coding-stage boundary, push task-owned changes and stop: no Actions polling, installation or automatic session restart. Documentation-only edits do not initiate that push. Do not ship alternative production implementations or optimization selectors for tests; ordinary correctness/capability fallbacks remain legitimate.

The baseline and every subsequent candidate use the [20–30-item daily-load contract](08-benchmarks.md#stage-a-daily-load-contract), ordinary external windows and normal backgrounds on both monitors. Report per-phase CPU/GPU/wait/work/resource/tail deltas alongside total interaction and frame outcomes. Distinguish exclusive costs, overlapped spans and unknown hardware/clock evidence. A neutral total can hide opposite changes or an off-critical-path gain; fine-grained observation still does not prove causal independence across shared resources.

Rank command-to-effect freezes, tails, affected workflows/outputs, frequency and evidence before implementation cost/risk. Measurement precedes blind rewrites. After A0, existing evidence puts P53 output demand/callback pacing, P60 native main CPU and the I/O/save boundaries first. Re-rank the next broad cycle after its combined report; do not repeat finished experiments merely because an umbrella task is open. Small inexpensive gains remain eligible without a minimum percentage. Keep measured tradeoffs and affected correctness explicit; no arithmetic addition of overlapping percentages or new blanket regression policy.

The user's other agent owns sync/history-saving, database-lock and Karma bug fixes. P94 is reserved for that effort. Coordinate overlapping mutation/transaction/access/effect changes before coding, consume source-identified results and continue independent work while an owner is blocked. Delegation is not a performance pass.

P151 supplies common accounting; P152/P153/P102/P36 finish specific measurements; P154/P93/P155/P156/P104 deliver the selected combined suite and results. P140–P146 retain their refinement/safety dependencies and mandatory Protein Add filter first. P70 supplies consumer evidence to P67/P55; P60 precedes dependent P61; P62 needs a coherent epoch handoff; P109/P78 feed style representation/application. P102 feeds coordinated save work. Do not substitute unavailable physical GPU/input evidence with a private-fixture pass.

A0 baseline/coverage tasks requiring an installed artifact remain pending after their hooks are coded; annotate exactly what the new binary must prove. A1 is not a command to implement every speculative theory: finish all justified ready owners, record unsupported/blocked alternatives and preserve behavior. A2 gates are evaluated together for every relevant new binary, not postponed until B or until every idea has been implemented. P135's existing appearance failure and P140/P146 coverage gaps remain explicit.

The Stage column assigns A0 tooling/baseline, A1 production work, A2 combined acceptance or deferred B. B includes general coverage expansion, build-only cleanup, compiler experiments and fullscreen-only scanout. Promote a B task only for an evidenced A bottleneck or indispensable validation blocker. A0's focused suite is required; unrelated platform productization is not. See 12 for exact report, source ownership and stopping rules.
