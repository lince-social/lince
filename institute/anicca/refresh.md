## Goal and acceptance contract

An agent working in a terminal finishes a development cycle, runs the delivery command, receives a truthful confirmation that the requested binary is actually running, and continues work in the same terminal and session. A human must not need to log in again between qualified cycles. A separate validation subagent may inspect the installed candidate after a cycle; it must report which source and executable it observed.

The owner accepts a visibly rough transition: a held frame, flicker, temporary blank output or brief visual pause is acceptable. This does not waive session preservation, application state, supported behavior, correctness, security or steady-state performance. Transition duration and resource peaks must be bounded and reported even though visual polish is not a release gate. A visual pause is not permission to cancel jobs, lose input, break calls, discard drafts or reset ongoing work.

The feature must replace the active Park implementation, including its compositor/session core when that code changes. Installing a file, changing a symlink, replacing only the UI worker, retaining an indefinitely old Park core, recreating windows after killing applications, or keeping only a tmux job alive does not complete this goal. Third-party applications must not need reconnect support or a relaunch to survive.

No degradation of a required feature or established performance metric may be hidden as the cost of refresh. Preserve normal graphics quality, output configuration, input behavior, native and external windows, background semantics and durability. Prove preservation with matched measurements and feature checks; do not promise zero overhead from an architecture drawing. Existing unrelated failures stay identified as existing failures. Missing coverage is not a pass, and no default regression allowance is introduced by this plan.

Old Lince versions are not a product compatibility target. There is nevertheless a concrete state-transfer contract between the currently running generation and its intended successor. Supporting that single transition and recovering its failed attempt is required for this feature; it does not imply maintaining arbitrary historical versions.

## Architecture to prove before committing to a large refactor

The preferred investigation is a complete, explicit state handoff at a quiescent boundary, initially attempting exec in the same Park PID. Normal rendering and input should keep their current direct paths. A small coordinator waits for upgrade requests and process/readiness events outside those paths. It must have no polling loop, frame relay, input forwarding loop, per-frame serialization, extra renderer or steady-state worker added solely to make refresh possible.

At a high level:

```text
Normal operation:
applications <-> current Park, with its normal rendering/input/data paths
                   ^
                   | authenticated upgrade control, normally idle
                coordinator <-> xtask

Refresh:
prepare candidate -> quiesce old generation -> checkpoint state and descriptors
-> replace executable -> restore state -> prove usable operation -> acknowledge
```

This is a design hypothesis, not an existing backend capability. Linux can preserve selected descriptors across exec, but exec discards the process's stack, heap and mappings. Unix descriptor passing also preserves references to open resources, not a Rust object graph. The Wayland backend, Smithay protocol state, graphics ownership and Lince runtime must explicitly support export/import. The exact compiled backend must be audited; do not infer support from the existence of a socket API.

The coordinator may be integrated into the existing control/event loop or be a small separate process when resource escrow and crash recovery require it. A separate coordinator must block on kernel events and participate only in refresh and recovery. Measure its memory, CPU and wakeups. Keeping a client endpoint alive through an extra duplicate descriptor must not disguise a failed restore as a timeout, as the initial probe refinement demonstrated.

A permanent session-core/replaceable-worker split remains an alternative to compare if complete handoff is infeasible. It is not an automatic fallback that satisfies the request: it must demonstrate unchanged metrics and also solve upgrading that core. Likewise, dynamic library unloading, raw pointer preservation, toolkit reconnection and generic process checkpoint/restore are not assumed solutions. A process checkpoint that resumes the old program is not proof of running the new program. Any alternative must pass the same full contract before it replaces this design.

## Connection backend extension and observed transport proof

This phase adds maintained copies of locked `wayland-backend` 0.3.17 and `wayland-server` 0.31.14, with their upstream revision metadata and MIT licenses. Package generation includes both licenses. The normal client/server dispatch paths and data layouts have no new runtime fields or hooks. The DTO retains client/object IDs and serials, registry bindings, compiled wire-interface identities, object-map holes, allocation capacities, actual inherited resource versions, unread/unsent userspace bytes, queued descriptor order and application-owned encoded payloads. File descriptors are duplicated with close-on-exec by default. Import validates bounded metadata and the recreated globals, constructs new typed application data, and only installs client polling registrations after staging the complete set; a registration failure removes registrations already added. It does not dispatch client requests while preparing import. The caller must coordinate an actual quiescent boundary: clones and application threads must not mutate protocol/user data during export. Encoder callbacks run after releasing the internal backend lock so typed serializers can perform lookups without deadlocking that lock.

Factories themselves must stage application side effects and correctly restore counters/credentials/grants; import does not announce an old connection as newly initialized. ## Open decisions and stopping conditions

1. Can the selected Wayland backend support a complete typed export/import, and what maintained dependency work is necessary? R06/R07 are the first feasibility gate.
2. Can seat/DRM/input and every active graphics resource be restored across same-PID exec on the supported hardware without changing normal performance? R11/R12 decide this separately from the headless proof.
3. Which native/backend operations require explicit continuation machinery rather than simple descriptor/state transfer? R05/R13/R14 must enumerate them; an unhandled feature cannot be omitted.
4. Is a separate sleeping coordinator necessary for post-exec recovery? Choose it only after the ownership and failure experiments identify its job.
5. What is the permitted bootstrap for the currently running pre-handoff executable? The user has not authorized closing that session to discover an answer.

If a gate fails, retain its evidence and unfinished checkbox, describe the precise blocker and refine the architecture with the owner. Do not reduce the goal to worker-only updates, toolkit-specific survival, lower quality or worse established metrics. During eventual implementation, remove task text only when its required implementation and acceptance are complete, retaining deferred work and blockers; delete this plan only when all agreed work is finished and its evidence/operational instructions have an agreed durable home.

## Primary technical references

- [Linux execve](https://man7.org/linux/man-pages/man2/execve.2.html): executable replacement initializes new program memory; selected descriptor inheritance is a separate concern. This explains the need for explicit state restoration, not an assurance that Park resources are transferable.
- [Unix domain sockets](https://man7.org/linux/man-pages/man7/unix.7.html): descriptor/credential passing primitives for a control and resource-transfer design. Passing a descriptor does not restore protocol/application objects.
- [Wayland protocol model](https://wayland.freedesktop.org/docs/book/Protocol.html): object identifiers, asynchronous requests/events and client/server state that the handoff must preserve.
- [Linux epoll_wait](https://man7.org/linux/man-pages/man2/epoll_wait.2.html): an event-driven control path can block indefinitely while idle; its real overhead still requires measurement.

These sources establish primitives. The applicability and complete-feature feasibility of the proposed Park handoff remain engineering work in the unchecked tasks above.
