## Implemented behavior

- Ordinary Karma/Frequency consequences reopen a reusable Need or repeat a Transfer. Reopening creates an ordinary linked child and keeps one unresolved demand; signed past occurrences remain intact. Repeats run on Frequency events, with explicit proposal/publication/own-commitment/activation stages. Activation waits in a normal guarded Karma rule for current agreement; it creates no receiver-confirmed report. Desktop and mobile entry points open the shared Karma editor. The separate stock-policy model, forms and obsolete tests are removed; ordinary quantity limits and reservations remain.
- Ordered address Records describe a larger transport route. Contributions to individual legs use normal linked Transfers. Capacity is counted on occupied segments, with independent progress/sharing/confirmation. The composer and detail views expose stops and part creation without requiring a map. Segment addresses follow location disclosure.
- Shared native controls provide reviewed place search, reverse lookup, routes, distance, estimated arrival, cancellation and provider settings. Small local place indexes work offline. Configured services use the [Nominatim search/reverse protocols](https://nominatim.org/release-docs/latest/api/Search/) and [OSRM route protocol](https://project-osrm.org/docs/v5.24.0/api/). Requests require explicit permission, use configurable intervals, bounded responses and no redirects. Settings save atomically. Route geometry uses customization tokens and bounded overlay geometry; background completion wakes the UI.
- A selected region can be prepared as a verified Shortbread tile directory with coverage, zoom, hashes, source, license and credits. Preparation reuses the current tile store and normalization, omits buildings, respects quota/cancellation and publishes a finished new directory. Native and mobile share controls. The equivalent command is `cargo xtask map-region <source-settings.json> <region.json> <new-output-directory>`. Existing import controls load the result; detailed global data is optional.
- Credentials and activity recommendations extend signed profile statements, with issuer/subject, exact vocabulary scope, validity and signed withdrawal revisions. They remain separate from receiver-confirmed delivery quantities. Native/mobile profile controls expose them and reader source checks. Supplier matching uses an authored Need, visible uncommitted offers, exact units/meanings, availability, optional distance and selected reader filters/weights. Existing Needs and saved reader policies can be selected by name through a shared structured-choice control. Matching returns candidates for normal review and performs no transfer execution.

Routing requires a configured local or remote routing provider and its routing data; display tiles supply no routing graph. The small world overview remains available independently. Signatures establish authorship and integrity, while physical delivery and resistance to fake identities still depend on the reader's evidence choices.
