[Official service documentation](https://docs.versatiles.org/guides/use_tiles_versatiles_org).

Verification found and corrected four production defects:

- Switching the desktop navigation identity scope cleared results and endpoints but retained the typed private query. It now clears the query too.
- Mobile review ran Transfer preset binding on ordinary action forms, inserting `promises: null` into credential requests. Shared binding now accepts draft forms only; the credential request deserializes through the normal reviewed-action path.
- Shared search/routing buttons had handlers but no layout nodes, so they were invisible in the rendered interface. Both hosts now get visible themed buttons with 44 px minimum height and an explicit scroll position for the provider panel.
- Supplier matching treated Protein's leading `transfer_context` row as the requested offer. It now selects the row with the requested Transfer UID.

The supplier fixture now explicitly includes an owner-only source and a source disclosed to participants. It verifies the exact visible candidate, repeated searches without persistent changes, conservative rejection for missing time/location constraints, zero-weight/excluded evidence, signed withdrawal and no occurrence creation. Withdrawal uses `ReviseTransferDraft`; it does not alter Transfer quantity directly or address an already accepted invitee again. Lifecycle and visibility guards were preserved.
