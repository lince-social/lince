# 11a — Electronic systems, schematics and PCB authoring

Finish with a reusable electronic device whose schematic, board layout, 3D assembly and functional behavior share stable identities and one accepted edit path. Its internal design remains editable while ordinary scene use runs a cheap functional model. This stage delivers electronic authoring and design checks; numerical circuit execution begins in stage 15a.

## Required workflow milestones

- [ ] **11a.M01.** Create a hierarchical schematic with declared component pins, nets, supply/reference connections and exposed device ports. Select the same component or pin from schematic, table and scene; edit, undo and reopen without losing identity.
- [ ] **11a.M02.** Realize the bounded design as a two-copper-layer PCB: assign compatible footprints, place components, route traces and plated through vias, and inspect the board in its CAD enclosure. Cross-probe schematic pins, footprint pads, copper connectivity and 3D occurrences.
- [ ] **11a.M03.** Run the declared electrical and board checks, inspect diagnostics by stable selection, repair an intentional open/short/clearance error and export the supported fabrication package with exact source revisions and limits. Passing checks does not claim manufacturing yield or electrical performance.
- [ ] **11a.M04.** Expose the board as a reusable sensor device, choose its stage 07 functional model and use it in the room while internal geometry is unallocated. Reopen the PCB, edit it, inspect stale approximation status, preserve unselected copies and save offline.
- [ ] **11a.M05.** Create the device abstractly first, then associate a detailed implementation through explicit port/model mappings. Share an allowed schematic or coarse device with a restricted visitor without revealing private internals or executing supplied code.

## Ordered implementation tasks

- [ ] **11a.T01.** Freeze B43 inputs, source/library rights, board rules, supported geometry and import/export subset. Record counts/bytes and independent expected connectivity/check results. Select the concrete interchange codecs by examining a small attributed round-trip fixture before implementation; keep proprietary/vendor-specific remainder explicit.
- [ ] **11a.T02.** Implement revisioned electronic definitions and mappings: symbol pin ↔ logical terminal ↔ footprint pad ↔ package occurrence ↔ optional simulation-model terminal. Store reference designators as labels, not identity. Support hierarchical modules and explicit external terminals without assuming every chip exposes its internal circuit.
- [ ] **11a.T03.** Deliver the native schematic editor and component/net inspector: place, connect/disconnect, name a net, expose a module port, select/cross-probe, inspect properties, preview/cancel, undo and save. Use the same authorized commands for native and Agent operations. Connectivity follows explicit nets and validated copper extraction; crossing drawn wires or touching meshes alone does not connect terminals.
- [ ] **11a.T04.** Deliver footprint assignment, board outline/stackup, placement/rotation, keepouts, trace routing and through-via editing. Derive copper connectivity and geometric checks through bounded jobs keyed to the accepted revision. Show unrouted connections and conflicts; integrate board/enclosure clearance through existing CAD/assembly selections. Do not require the electrical graph to be a tree.
- [ ] **11a.T05.** Implement the supported electrical-rule checks for pin roles, missing required supply/reference connections, unconnected required pins and conflicting declared drivers. Implement board checks for net shorts, opens, minimum clearance, width, drill/pad bounds and board-edge clearance within B43's geometry subset. Preserve waived diagnostics with reason and source revision; stale or incomplete analysis is not a pass. These are declared design-rule checks, not general electrical correctness certification.
- [ ] **11a.T06.** Export a revision-pinned bill of materials, machine-readable connectivity, placement data, supported copper/mask/outline artwork and drill data. Choose and document the exact Gerber/drill/placement subsets against independent readers and a reviewed fixture; preserve units, origin, rotations and top/bottom conventions. Unsupported manufacturing outputs remain unavailable rather than plausible approximations. Imports preserve lineage, mapping conflicts and permitted library dependencies without fetching or executing arbitrary referenced content.
- [ ] **11a.T07.** Bind the module to stage 07 functional models through validated external ports and an explicit association to its internal implementation. Support both abstract-first and detailed-first authoring. Editing the circuit or board invalidates only dependent checks/exports/derived behavior; an independently authored behavior specification retains its identity, while its claim to describe this implementation requires renewed evidence. Functional execution never activates dormant circuit/component evaluators.
- [ ] **11a.T08.** Complete native cross-view, offline, hosted, denied-edit, stale-result and source-conflict replays. Integrate revisioned component quantities with stage 11 takeoff for stage 13 procurement; preserve operational authority. Add the stage 15 regression contract and leave circuit solving pending for 15a.

## Architecture and task requirements

- [ ] A reusable component separates logical pin roles, schematic appearance, physical package/footprint, purchasing metadata, functional model and optional numerical device model. Matching by display name is insufficient. Explicit mappings validate coverage, terminal kinds, units and revision; unsupported pin mappings block the affected operation while the rest remains inspectable.
- [ ] Schematic, PCB and 3D placement are related representations with different editable data. A board-placement edit changes its accepted placement and dependent geometry; it does not silently rewrite schematic connectivity. An intentional net edit invalidates layout connectivity/check results and shows required repair. Source updates preserve known correspondence and expose deleted/split/ambiguous pads or pins.
- [ ] Enclosures, connectors, mounting holes, board dimensions, component heights and keepouts use the same CAD frames/units and assembly interfaces. Library 3D appearance may be approximate; measurement and manufacturing use only the declared suitable source. Trace shape may later supply resistance/parasitic extraction, but no such prediction follows merely from drawing copper.
- [ ] A module's external contract includes required/optional ports, outputs, initialization and model validity. An electrical supply terminal and the core functional `supply_available` signal remain distinct. Stage 15a supplies the explicit electrical-to-functional adapter; no hidden Boolean-to-voltage conversion is built here.
- [ ] A label such as camera does not generate optics, firmware, protocol or semiconductor physics. Use an implemented behavior template with stated capabilities. A motion-sensor board may initially accept an idealized scene-stimulus input; its mapping is an assumption until a separately validated transducer model replaces it.
- [ ] Native tooling includes schematic canvas, board layers/routing view, component/net table, 3D cross-selection and diagnostics. Keyboard/numeric tools, scope, focus, accessible status and undo follow the existing workspace contracts. Model selection remains in the shared stage 07 inspector, including unsupported/stale status; do not introduce a separate electronics runtime control system.
- [ ] Bound nested modules, connection counts, polygon complexity, library decode sizes, queued checks and exported bytes. Reuse source assets across instances; count unique boards and occurrences separately. Imported executable models remain inert artifacts until a trusted installed evaluator is explicitly admitted at its later stage. Embedded library/dependency licenses and credits accompany the relevant Sand/assets.

Build the same external device abstractly, associate the board explicitly, and share only its permitted projection. Verify no solver, arbitrary code or external equipment action starts.
