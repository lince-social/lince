# Trail under the rebirth architecture (docs/fable-improvement.md)

A Trail is not a built-in feature. It is a shape made entirely of the rebirth primitives — which is what makes it powerful and shareable:

- **A collection of Records**: the subjects, steps, exercises, materials, tools. Each carries head/body for the human explanation.
- **Links define the order of implementation/learning**: `link(from, kind, to, quantity?)` with kinds like `@requires`, `@before`, `@part-of`. The link graph *is* the curriculum/blueprint order. Link quantities carry exact amounts: "2 hours of practice", "500g of flour", "3 repetitions" — a recipe and a syllabus are the same structure.
- **Lingua concepts on every Record** so a Trail transplants between Organs: measures, units, tools, and subjects mean the same thing to the author and to the student. Importing a Trail can also import the concepts it uses (same one-tap adoption as any Lingua import).
- **Publication through the ordinary package flow** (the same used for sands): a Trail is an importable subgraph — records + links + concepts + optional Karma rules (habit counters for practice) + views.

Pulling Trails from several Organs merges them into a personal knowledge base: imported records keep their concept identity, so two Trails that touch fermentation connect on their shared concepts instead of duplicating them.

The community goal: a public library of Trails, built by many Organs, from basic subjects up to PhD-level knowledge — education and production blueprints in one format, because "how to learn X" and "how to build X" are the same graph shape.

Personal progress through an imported Trail is a separate concern — see 'Trail Progression Management'.
