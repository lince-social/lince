THE CHECKED-IN ANICCA CONTRACT
==============================

AUTHORITY
---------

The repository-root `anicca/` is the one checked-in source tree for Lince
documentation, declarations, and the task plan. `anicca/Lingua.lingua` carries
the living explanation. `crates/anicca/src/grammar.rs` is the only syntax
authority: a typed Rust grammar compiled by `rust-sitter` and shared by the
parser, formatter, checker, and projection.

Do not write new declarations under `docs/records/`, invoke a JavaScript
converter, or route Anicca through `crates/engine/src/lingua_file.rs`. Those
belong to the superseded fenced-prelude format and are not a compatibility
contract.

THE RECORD
----------

    "The Lingua DSL" (@lingua: 0, is #chapter, #instinct, #part-of @ontology) {
    The description is ordinary Markdown.
    } ^r_XXXXXXXXXXXXXXXXXXXXXXXXXX

An unqualified top-level declaration is a Record. Its quoted title precedes `(`. Its
first header value is either `@slug: quantity` or a bare quantity for a
slugless Record. A slugless Record remains uid-identified but cannot be named
by an authored `@slug` reference.

`is #concept` is identity. `#concept` is an ordinary assertion.
`#predicate @target` is binary. `#predicate: quantity` carries an exact amount.
Record quantity and assertions such as `#done` are independent.

The optional `^uid` after the closing brace is machine-owned. A person may
omit it; Lince mints and writes it before database projection. Local references
stay slug-only and are resolved project-wide to immutable uid identity.

`"Karma" (0) { ... }`, `"Rule" (0) { ... }`, and `"Record" (0) { ... }` are
ordinary Records with those titles. Executable Karma is structurally distinct as
`Karma name { Rules { Rule name { ... } } }`.

FORMATTING AND COMMENTS
-----------------------

Record metadata stays on one line through 150 characters and expands to one
entry per line after that. `//` comments after metadata commas are retained.
Inside a description, `//` is ordinary Markdown. A `}` in column one closes a
Record description; indent a literal description line beginning with `}`.

FAIL CLOSED
-----------

Duplicate slugs or uids, malformed typed uids, unresolved references, unknown
declarations or fields, and invalid quantities refuse the complete project.
Never infer identity from a title or create vocabulary as an import side
effect.

CHECKS
------

    cargo run --offline -p anicca -- check anicca
    cargo run --offline -p anicca -- fmt anicca
    cargo test --offline -p anicca

Parser and File Sync changes additionally run the engine File Sync tests and
`cargo check --offline -p engine`.
